# NovelAIで漫画原作を書いてもらう

> 最新の使い方は、アプリ右上の「使い方」で開くガイド（[novelai-story.html](../web/guide/novelai-story.html) ほか4ページ）にまとめました。この文書はNovelAI用システム指示の補足と、小説APIの確認記録です。

作成・公式情報確認: 2026-10-14。2026-10-17にページ割りに合わせて整理。

[novelai-visual-novel-system.txt](novelai-visual-novel-system.txt) は、全文をコピーできる通常小説用のシステム指示です。地の文と会話で普通の小説を書かせ、ページ数とコマ割りはこのキットのページ割りとStrataへ任せます。

2026-10-17: ページ割り（キット側で原作を各ページへ割り振る機能）の導入に合わせ、【出力の形】を更新した。区間見出しのページ番号（P01〜P04相当）、1回1〜4ページの制限、末尾の【次区間への引継ぎ】をやめ、`## 第一章　章のタイトル` の章見出しで区切る形にした。古い区間方式の原稿をキットへ貼るときは、引継ぎメモを消す（ページ割りが出来事として扱うため）。

「感情を消す」のではなく、気持ちを表す動作・表情・台詞を書く方針です。「何が見えるか」を具体的にしつつ、約束や判断など、絵だけでは伝わらない因果関係は短い会話などに残します。画風と英語の画像プロンプトはMangaAgentsStudio-S側で設定します。

## NovelAIでの貼付先

Xialong／GLM-4.6では、Advancedタブの **System Prompt** へtxtの全文を入れます。公式英語版は両モデルに対応と記載しています。Prefillは別の欄です。[公式Advanced Settings](https://docs.novelai.net/en/text/editor/advancedsettings/)

今回の題材・作成範囲は本文側の依頼へ、固定の人物設定などはMemory／Lorebookにも置いて運用できます。Author's Noteには必要なら短い作風指示だけを置き、長いシステム指示の全文を重複させない構成を提案します。MemoryとAuthor's Noteでは文脈への挿入位置が異なります。[公式Story Settings](https://docs.novelai.net/en/text/editor/storysettings/)

System Prompt欄がないモデルでは同じ設定方法になりません。固定設定をMemoryに置き、Author's Noteへ下の短縮版を入れ、本文の書き出しを用意する使い方があります。各モデルでの実生成比較は行っていません。

短縮例:

```text
地の文は人物の動作・表情・視線・距離、見える背景と小物を中心にする。心理は短い台詞や観察できる動作で表し、行動の理由は残す。外見・口調・場所・小物の所在を揃え、今回の章だけを自然な小説として書く。
```

これは **NovelAIの小説生成側** へ渡す指示です。Sの「① 共通システムプロンプト」はStrata向けなので、このtxtをそのまま同欄へ入れる用途ではありません。

## 依頼・続き・キットへの渡し方

Memoryの書き方、本文での依頼、続きの章の依頼、キットへの貼り付けは、ガイドの [NovelAIで小説を書く](../web/guide/novelai-story.html) に [迷子のカメラ](lost-camera-12.txt) を題材とした例があります。要点は次のとおりです。

- 初回は「# 作品名」、短い「【共通設定】」、`## 第一章　章のタイトル` からの本文の順にします。続きは同じストーリーの末尾へ、次の章だけを依頼します。共通設定は繰り返しません。
- 「## 」は章の区切りだけに使います。キットは最初の見出しより前を毎回渡す共通設定とし、`## ` の行で章を選べるようにします。原作全体は200,000文字、今回選択した章は共通設定込み30,000文字以内です。
- NovelAIの**生成結果**だけをコピーします。`{ }` の依頼文、使わなかった生成、「承知しました」等やAIのメモは作品本文へ混ぜません。
- ページ数はキットのページ割りで決めます。小説側でページ番号やコマ番号を書かせる必要はありません。
- 新しい固定設定は共通設定へ追記します。既存人物の外見や口調を変える場合は、Sの共通台帳も画面から明示的に変更してください。保存済みのページが原作更新だけで書き換わることはありません。既存ページを変える操作は「改稿」、新しいページは「続きのページを追加」です。

現行Sの話者欄は、そのコマに映る人物IDか未指定です。原作上必要な画面外の声がある場合は、Strataへの指示に「画面外の人物を画像に追加せず、話者欄は未指定、場面メモに本来の話者を残す」を添えます。発話／独白などの種別も原作と場面メモで保持し、別形状のフキダシへの自動変換はしません。

小説は原作テキストとして受け渡します。**「作成済み字コンテJSONを取り込む」「設定JSONを取り込む」へ入れる形式ではありません。**

## 小説生成APIについて

**外部プログラムから呼び出せます。** 公式仕様に次の経路があります。認証はPersistent API tokenをAuthorizationヘッダーへ渡す方式です。[公式APIスキーマ](https://text.novelai.net/docs/doc.json)

| 用途 | エンドポイント（ホストはtext.novelai.net） |
|---|---|
| system／userのメッセージによる生成 | `POST /oa/v1/chat/completions` |
| 文章の続きを生成 | `POST /oa/v1/completions` |
| 上記互換APIのモデル一覧 | `GET /oa/v1/models` |
| 従来の小説生成 | `POST /ai/generate`、`POST /ai/generate-stream` |

このシステム指示は、対応するチャット形式モデルのsystemへ指示、userへ依頼と設定を渡す形にできます。モデルIDは一覧から選び、従来エンドポイントと同じIDが必ず使えるとは仮定しません。Memory／Lorebook等の必要な情報は、外部呼出し側で入力へ組み立てます。

有効な定額契約のテキスト生成は公式案内で無制限とされ、ImageAnlasは画像用です。利用できるモデル、入力・出力上限、レート制限は別に適用されます。[公式サブスクリプション案内](https://docs.novelai.net/en/subscription/)

現行Sに小説生成の常設機能はありません。2026-10-14に、今回限定のスクリプトからXialongへ字コンテ形式のsystemと8ページの依頼を渡し、4ページずつ2回の実生成に成功しました（この字コンテ形式の指示と依頼文は公開版に含めていません）。各回のAnlas差分は0。返却されたtoken_idsを公式GLM-4.6 tokenizerで復号しています。原稿には衣装・画面内人物の食い違いがあり、漫画化用に補正しました。通常小説用プロンプトでのAPI経由の実生成と、他モデルの比較は未検証です。
