保存上限と、制作AIに渡す上限

原作を保存できても、その全体を一度の処理で渡せるとは限りません。長い原作は ## 第一章 のような見出しで分けます。最初の章見出しより前は共通設定です。見出しがない原作は全体を1区間として扱います。

処理上限数える範囲
原作の保存200,000文字project.json の source。章分けや共通設定も含む原作全体。
ページ割り90,000文字studio/pageplan.py が組み立てる入力JSON全体。開始ページ、目標ページ数、共通設定、開始章から最後までの章番号・章題・本文、直前回の終了ページ・引継ぎ、構成の希望を含む。原作本文だけの9万文字ではない。
字コンテ作成に渡す原作30,000文字共通設定＋対象章のテキスト。ページ割りから複数章が選ばれた場合はその合計。台帳やシステム指示の上限とは別。
短い制作AI処理95,000文字ページ割り・翻訳・点検等の初回メッセージ列をJSON化した長さ。システム指示と入力JSONのエスケープ等も含むため、ページ割りの90,000文字を満たしても止まる場合がある。
字コンテ・コマ修正のツール往復100,000文字各ターンの会話メッセージ列をJSON化した長さ。原作だけでなく台帳・直前ページ・ツール結果等も含む。
ページ数1作品24ページ字コンテは1依頼1〜4ページ。最後までの自動作成は同じ章の中で最大2ページずつ。

文字数はPythonの文字列の長さで検査します。バイト数やモデルのトークン数ではありません。JSONの上限にはキー名・括弧・区切り・エスケープも含まれます。原作を短くし、ページ割りの開始章や1回のページ数を調整してください。24ページを超える場合は引き継ぎ用の設定JSONで別作品へ進む方法があります。

保存先とバックアップ

work/<作品ID>/project.json が編集の正本です。画像候補と採用画像は区別して保存します。保存時に競合した変更は上書きしません。

場所（作品内は work/<作品ID>/ からの相対パス）内容
project.json／source.txt正本の原作・人物台帳・プロンプト・採用画像／原作の参照用コピー。
history/保存前の作品JSON。
images/<コマID>/候補PNG、送信要求、生成記録。NovelAIは生成前後の残量も記録。
images/page-001/／images/previews/ページ一括の候補／試し描き。コマ別の候補とは別に保存。
images/previews/／images/references/Qwenで登録した試し描き／ローカル補助関数で取り込んだ参照画像。
output/page-001.png／output/overview.png組版したページ／全ページ一覧。
output/manifest.json寸法、枠、原画、クロップ、文字位置等の配置情報。
agent-runs/制作AI（Strata／Grok）の実行履歴。Grokの費用はCLIが報告した範囲のみで、欠落は無料を意味しない。
imports/Aからの取込元本文・前回入力・対応表・差分の確認理由。再取り込みの比較に使うため、作品と一緒に保管。
exports/<書出しID>/download.zipPNG／PSD・台詞md・設定JSON・配置情報の書出し。
アプリ直下の .runtime/anlas-ledger.json全作品共通のNovelAI費用記録・停止状態。作品ZIPの対象外。

作品のバックアップは work/_backups/<作品ID>/ のZIPです。アプリ起動時と30分ごとに、前回の自動バックアップから版が変わった作品を軽量版で保存し、自動分は作品ごとに最大20世代を残します。手動分は自動削除しません。

バックアップ含むもの含まないもの
自動／「今すぐバックアップ（軽量）」原作・設定・履歴・要求・記録等画像。完成ページの output/ と書出しの exports/
「画像も含めてバックアップ」上記と候補画像・Qwen参照画像output/ と exports/

復元はZIPから作品フォルダを取り出す手動操作です。復元手順に従い、完成ページ・書出しは作り直します。アプリ全体を別途保管する場合は work/ と .runtime/ の費用・生成記録も保管してください。原作・画像・要求・履歴を含むため、公開リポジトリへ一括登録しないでください。

「この作品を削除…」は work/_trash/ への移動です。完全削除・復元はゴミ箱の操作手順を使います。「一覧から除外」は一覧の表示だけを変え、ファイルを移動しません。

出力と画像の位置

ページは1200×1800、1〜7コマ、84種のコマ割り（基本5種＋MangaAgentsStudio-A由来79種）です。斜め枠にも対応します。台詞はPillowによる横組みです。自由なコマ枠のドラッグ編集・縦組みは未対応です。

「全ページを書き出す」はサーバー側でZIPを作ります。PNGまたはPSD＋確認用PNG、台詞一覧 dialogue.md、設定JSON、配置情報を含みます。PSDの文字は分離したラスターレイヤーで、ネイティブ文字編集には対応しません。psd-toolsによる再読込・合成一致に検証記録がありますが、Photoshop／CLIP STUDIOでの実読込は未検証です。

Seed空欄はランダムです。過去のSeedは候補の説明・要求JSONから確認できます。クロップ横・縦は0〜1で、0が左／上、1が右／下。枠より縦長の画像はクロップ縦を0へ寄せると頭部を残せます。「位置調整」ではドラッグ・倍率10〜400%・全体を収める配置もできます。原画は変更せず、PNG／PSDは同じ配置計算を使います。位置調整の操作。

Aから取り込んだプロンプトの編集

MangaAgentsStudio-Aの取り込みには配布フォルダの skills/manga-a-import と python -m studio.a_import を使います。通常の設定JSON読込みや作品フォルダ読込みへAのファイルを直接渡す機能ではありません。初回は空のNovelAI／コマ別作品へ取り込み、以後は同じ作品へ再取り込みします。取り込みだけでは画像を生成しません。

ページ／コマ個別 → NovelAIのプロンプト合成・配置 で送信方式を確認できます。「台帳の外見・衣装・背景・画風を合成」は通常のSの編集方式。「原文をそのまま使用」はコマにある場面・人物・除外の全文を送り、共通台帳や画風、品質語を追加しません。原文方式のコマを台帳方式へ変えるときは、同じ外見・衣装を本文と台帳へ二重に残さないよう整理してください。

人物ごとの除外プロンプトは日英で編集できます。配置ピン・入力順の正負それぞれの設定も保持します。これらの個別設定や原文方式を使う作品はコマ別生成で編集します。Aのモデル・寸法・sampler等はSの固定設定へ変わる場合があり、同seedでも同じ絵の再現は保証しません。Aの画像候補・費用・文字の縦書き／自由配置は取り込み対象外です。

再取り込みは前回A入力・現在のS・今回A入力を比較し、両方で変えた同じ項目やAで削除したコマは競合として止めます。同じコマIDの採用画像・候補は保持し、入力が変わった画像は必要に応じて再生成します。取込記録は imports/ に保存され、バックアップと作品フォルダのコピー読込みに含まれます。全入力の設定JSONだけでは、この再取り込み履歴は移せません。

ページを1枚で生成する（試験）

  1. 作品作成時に ページ一括生成（試験） を選びます。既存作品は「作品専用」→「作品の管理（バックアップ・削除）」→「生成方式を変更（上級）」で変更できます。画像モデルの変更とは別です。
  2. 「ページ／コマ個別」でページ設計JSONを確認し、「送信形式」で漫画用の文章・JSON・YAMLを選びます。
  3. 「フキダシと文字」で 後付け（台詞なしPNG・分離PSDに対応） または 画像モデルが画像内へ描く を選び、保存して1ページ生成 を押します。

JSON／YAMLはプロンプトの表現方法です。NovelAIやQwenの公式漫画スキーマではありません。画像はページごとに1枚ずつ生成します。コマ別画像とページ一括の候補・履歴は別々に保持します。

後付けならアプリが載せた台詞を分離できますが、原画へ混入した文字は消せません。画像内描画では台詞変更にも再生成が必要で、その採用画像の台詞なし書出しは拒否されます。画像内描画へ渡す台詞は、アプリでは改行込み374文字までです。

画像内の実コマ境界は検出していません。テンプレートと同じ境界・文字位置になる保証はありません。枠・文字配置を正確に扱いたい場合はコマ別生成を使います。NovelAIでの特徴。

設定JSONと旧形式

全入力・引継ぎ用は manga-studio-inputs-v4。旧v3の設定JSONは受け付けません。共通システム専用の manga-studio-system-v2 は別形式です。

「共通システム設定JSON」「引き継ぎ用の設定JSON」「全入力の設定JSON」は用途が異なります。引き継ぎ用は絵柄・システムプロンプト・人物・背景・小物を持ち、原作・ページは持ちません。設定JSONは画像のバックアップではありません。Qwen参照画像は引継ぎ先の作品で用意します。

作品・字コンテ・設定・ページ設計のJSONには output_method（novelai／qwen）が必要です。取込先と異なる方式や属性がない旧形式は拒否されます。画像モデルは作成時に固定され、モデル間の変換には対応しません。作成済み字コンテのひな形は配布フォルダの templates/board.example.json です。

通常のコマ編集とページ一括の設計は連動します。独立した設計が残る対応形式の旧作品では 元コマから作り直す で反映します。

templates/novelai-storyboard-system.txt はページ・コマを先に決める原稿用の指示です。出力を原作欄へ貼る形式で、JSON取込用ではありません。ページ割りとの組合せは未検証です。旧原稿に「次区間への引継ぎ」等の制作メモがある場合は、物語の出来事として扱われないよう本文から外します。

NovelAIの小説生成API（開発者向け）

アプリに小説生成APIを呼ぶ機能はありません。原作は利用者が用意して貼り付けます。外部プログラムから呼ぶ場合の公式APIスキーマには次の経路があります（ホストは text.novelai.net）。

用途経路
メッセージ形式POST /oa/v1/chat/completions
文章の続きPOST /oa/v1/completions
互換APIのモデル一覧GET /oa/v1/models
従来の小説生成POST /ai/generate、POST /ai/generate-stream

永続的APIトークンをAuthorizationヘッダーへ渡します。チャット対応モデルのsystemへ基本指示、userへ依頼と設定を渡し、モデルIDは一覧で確認します。Memory／Lorebook相当の内容は呼出し側で組み立てます。トークンを入力本文やログへ出さないでください。

有効な定額契約のテキスト生成は公式案内で無制限とされていますが、モデルごとの文脈長やレート制限等は別です。画像のAnlas管理とは分けて確認してください。通常小説用の指示を使ったAPI生成や他モデル間の比較は未検証です。
